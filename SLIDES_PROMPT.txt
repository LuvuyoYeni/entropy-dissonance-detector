SLIDE 2 — PROBLEM STATEMENT

Slide text:
- Phishing emails deceive recipients using social engineering, not malware
- Keyword filters fail: attackers rotate vocabulary to evade word-level rules
- Bayesian classifiers require labelled attack data — unavailable for novel attacks
- A detector trained only on normal email should flag anything that looks unusual

Research question: Can the statistical structure of normal email — specifically the joint distribution of lexical surprisal and syntactic entropy per sentence — be modelled well enough that phishing sentences score as anomalous without any labelled phishing examples at training time?

Speaker notes: Traditional spam filters rely on keyword lists or supervised classifiers trained on phishing examples. Both approaches have a fundamental weakness: an attacker who knows the filter can craft messages that avoid flagged vocabulary while retaining deceptive intent. One-class anomaly detection avoids this by modelling only legitimate email. Any email whose statistical properties fall outside the normal distribution is flagged. This project operationalises "statistical properties" as two entropy signals computed per sentence: H_lex (lexical surprisal) and H_syn (syntactic label entropy).

SLIDE 3 — RESEARCH HYPOTHESIS

Slide text:
Entropy dissonance hypothesis:
In normal email, lexical surprisal (H_lex) and syntactic entropy (H_syn) are coupled — they move together in a learnable joint distribution.

Phishing text breaks this coupling:
- Unusual vocabulary inflates H_lex
- Syntactic structure remains conventional — H_syn stays near normal
- The dissonance between the two signals is the anomaly

Prediction: A joint model of (H_lex, H_syn) will outperform a model of H_lex alone.

Speaker notes: The hypothesis draws on a known asymmetry in how humans craft deceptive text. Phishers manipulate lexical content — urgency words, impersonation phrases, action demands — but typically preserve grammatical convention because syntactic deviance makes text look broken or non-native. A sentence like "Your account requires immediate verification via secure portal access" scores high on lexical surprisal because those word combinations are rare in normal work email, but its syntactic role distribution (subject, verb, object, modifiers) is entirely conventional. The prediction is that encoding both signals in a bivariate Gaussian and scoring new sentences with Mahalanobis distance will capture this asymmetry. The experimental results challenge this prediction and the reasons are diagnostic.

Slide text:
Two detectors compared:

D2 — Baseline (H_lex only):
Raw email → sentence tokenise → word tokenise → trigram LM → per-sentence mean surprisal → threshold at μ + 2σ

D3 — Full system (joint H_lex + H_syn):

SLIDE 5 — FEATURE 1: H_lex (LEXICAL SURPRISAL)

Slide text:
Formula:
H_lex = (1 / n) × Σ −log₂ P(wᵢ | wᵢ₋₂, wᵢ₋₁)

Laplace-smoothed probability (src/features.py, lines 78–91):

[CODE BLOCK]
def score(self, word, context):
    V = self._vocab_size or 1
    if len(context) >= 2:
        c_w  = self._trigrams.get((context[-2], context[-1], word), 0)
        c_ctx = self._bigrams.get((context[-2], context[-1]), 0)
    elif len(context) == 1:
        c_w  = self._bigrams.get((context[0], word), 0)
        c_ctx = self._unigrams.get(context[0], 0)
    else:
        c_w  = self._unigrams.get(word, 0)
        c_ctx = sum(self._unigrams.values())
    return (c_w + 1) / (c_ctx + V)
[END CODE BLOCK]

Mean H_lex (normal): 12.570 bits   Std: 1.550
Anomaly threshold: 12.570 + 2 × 1.550 = 15.669 bits

Speaker notes: Without Laplace smoothing, any word sequence unseen in training receives probability zero. The original implementation used MLE (no smoothing) and silently skipped tokens with zero probability when computing H_lex. This meant phishing sentences full of unusual word combinations — the very sentences the system should flag — had their most anomalous tokens dropped from the average. H_lex values for highly anomalous sentences were therefore falsely pulled toward the normal mean. Adding 1 to all counts ensures no sequence receives zero probability. The denominator increases by V (vocabulary size, approximately 40,000 word types) to keep probabilities summing to 1. The practical effect: a trigram with zero count receives probability 1/(context_count + V) ≈ 0.000025, giving surprisal ≈ 15.3 bits — correctly flagged as anomalous rather than silently dropped. The score() method dispatches on context length: trigram formula for full 2-word context, bigram fallback for the second token of a sentence, unigram fallback for a context-free first token. H_lex is mean surprisal, not entropy — do not call it entropy.

SLIDE 5b — H_lex COMPUTATION LOOP

Slide title: H_lex — Computing Mean Surprisal Per Sentence

Slide text:
Per-sentence surprisal loop (src/features.py, lines 107–121):

[CODE BLOCK]
def compute_h_lex(sentence, model):
    tokens = [t.lower() for t in word_tokenize(sentence)
              if t.isalpha()]
    if len(tokens) < 2:
        return None
    surprisals = []
    for i in range(1, len(tokens)):          # start at 1: first token has no context
        context = tuple(
            tokens[max(0, i - NGRAM_ORDER + 1):i]
        )
        prob = model.score(tokens[i], context)
        if prob > 0:
            surprisals.append(-math.log2(prob))
    if not surprisals:
        return None
    return sum(surprisals) / len(surprisals)  # mean, not sum
[END CODE BLOCK]

NGRAM_ORDER = 3 (trigram). Loop starts at index 1 so every scored token has at least a 1-word context.

Speaker notes: The loop variable i runs from 1 to len(tokens)-1 inclusive. For i=1, context = tokens[0:1] — a one-word context, bigram probability. For i=2, context = tokens[0:2] — a two-word context, trigram probability. For i≥3, context = tokens[i-2:i] — always two words, trigram. The max(0, i-2) guard prevents negative slicing at sentence start. The function returns None if fewer than 2 alphabetic tokens are found, which upstream code handles by skipping the sentence. H_lex is the arithmetic mean of surprisals, not their sum — this normalises for sentence length so short and long sentences are comparable.

SLIDE 6 — FEATURE 2: H_syn (SYNTACTIC ENTROPY)

Slide text:
Formula:
H_syn = −Σₖ pₖ × log₂(pₖ)     where pₖ = count(label k) / total labels

Implementation (src/features.py, lines 124–138):

[CODE BLOCK]
def compute_h_syn(sentence):
    doc = NLP(sentence)
    labels = [token.dep_ for token in doc
               if token.dep_ != ""]
    if len(labels) < 2:
        return None
    counts = Counter(labels)
    total  = sum(counts.values())
    entropy = 0.0
    for count in counts.values():
        p = count / total
        if p > 0:
            entropy -= p * math.log2(p)
    return entropy
[END CODE BLOCK]

Normal mean H_syn: 3.401 bits     Phishing mean H_syn: ≈ 3.374 bits
Mean difference: 0.027 bits  (< 2% of one standard deviation)

Speaker notes: spaCy's transition-based dependency parser assigns every token a label describing its grammatical relationship to its syntactic head. Example labels: nsubj (nominal subject), dobj (direct object), det (determiner), prep (preposition), ROOT (main verb), amod (adjectival modifier), advmod (adverbial modifier), punct (punctuation). H_syn is Shannon entropy over the frequency distribution of those labels within a single sentence. A sentence with many distinct label types spread roughly evenly has high entropy. A sentence dominated by one or two labels has low entropy. The hypothesis was that phishing sentences would show lower syntactic diversity. In practice the H_syn distributions of normal and phishing sentences overlap almost completely. The mean difference of 0.027 bits is negligible. NLP is the spaCy en_core_web_sm model loaded at module level with NER disabled to save processing time.

SLIDE 7 — JOINT MODEL: BIVARIATE GAUSSIAN AND MAHALANOBIS DISTANCE

Slide text:
Manual covariance fit (src/full_system.py, lines 22–36):

[CODE BLOCK]
self.mu_ = X.mean(axis=0)          # [H_lex: 12.696, H_syn: 3.401]
diff = X - self.mu_
cov  = np.zeros((2, 2))
for row in diff:
    for i in range(2):
        for j in range(2):
            cov[i][j] += row[i] * row[j]
cov = cov / (n - 1)                # sample covariance
# cov = [[1.4950, 0.3306],
#         [0.3306, 0.3769]]
self.sigma_inv_ = np.linalg.inv(cov)
[END CODE BLOCK]

Mahalanobis score (src/full_system.py, lines 81–83):

[CODE BLOCK]
def _mahalanobis(self, h_lex, h_syn):
    x = np.array([h_lex, h_syn]) - self.mu_
    return float(np.sqrt(x @ self.sigma_inv_ @ x))
[END CODE BLOCK]

Threshold τ = 1.4625  (F1-optimal on validation set)

Speaker notes: The covariance matrix is computed without numpy's cov() function — a manual triple-nested loop accumulating outer products of mean-centred rows, divided by n−1 for the unbiased sample estimator. The off-diagonal entry 0.3306 captures the positive correlation between H_lex and H_syn on the normal training set (Pearson r = 0.44). The inverse Σ⁻¹ transforms the feature space so that the elliptical normal data cloud becomes a unit sphere, and Mahalanobis distance measures radial distance from the centre. The condition number is approximately 5.5 — well-conditioned, so numerical instability is not a concern. The pseudoinverse fallback (np.linalg.pinv) is a safety net that was never triggered. Threshold τ = 1.4625 is selected by iterating over all thresholds from the ROC curve on the validation set and choosing the F1 maximiser, subject to the constraint that it flags no more than 80% of all sentences.

SLIDE 8b — TRIGRAM MODEL FIT

Slide title: LaplaceTrigramModel — Fitting in O(n)

Slide text:
Model construction (src/features.py, lines 60–76):

[CODE BLOCK]
class LaplaceTrigramModel:
    def __init__(self):
        self._unigrams = Counter()
        self._bigrams  = Counter()
        self._trigrams = Counter()
        self._vocab_size = 0

    def fit(self, sentences):
        for tokens in sentences:
            for i, tok in enumerate(tokens):
                self._unigrams[tok] += 1
                if i >= 1:
                    self._bigrams[(tokens[i-1], tok)] += 1
                if i >= 2:
                    self._trigrams[
                        (tokens[i-2], tokens[i-1], tok)
                    ] += 1
        self._vocab_size = len(self._unigrams)
        return self
[END CODE BLOCK]

Single pass over all tokens. Three Counter dicts. No external libraries.
Vocabulary size after training: ~40,000 distinct word types.

Speaker notes: The fit() method iterates once over every token in every training sentence, incrementing all three counters in the same loop body. Time complexity is O(n) in the total number of tokens. Space complexity is O(k²) in the vocabulary size in the worst case (all bigrams seen), but in practice far lower because most bigrams never appear. The Counter dict key for trigrams is a 3-tuple of strings; Python hashes tuples efficiently. vocab_size is set after the loop completes because new tokens may be added throughout. No smoothing is applied during fitting — smoothing is applied at query time in score(), so the raw counts are always available.

SLIDE 11 — ADVERSARIAL EXPERIMENT

Slide text:
Attack: 30% WordNet synonym substitution on phishing test sentences. No retraining.

Substitution logic (src/adversarial.py, lines 51–66):

[CODE BLOCK]
SUBSTITUTION_RATE = 0.30

def _obfuscate_sentence(sentence, rng):
    tokens = word_tokenize(sentence)
    tagged = nltk.pos_tag(tokens)
    eligible  = [i for i, (w, p) in enumerate(tagged)
                 if p in _WN_POS_MAP and w.isalpha()]
    n_replace = max(1, round(len(eligible) * SUBSTITUTION_RATE))
    to_replace = set(rng.sample(eligible,
                                min(n_replace, len(eligible))))
    result = []
    for i, (word, pos) in enumerate(tagged):
        if i in to_replace:
            syn = _get_synonym(word, pos)
            result.append(syn if syn else word)
        else:
            result.append(word)
    return " ".join(result)
[END CODE BLOCK]

Results:
              Original AUROC    After attack    Change
  D2              0.8087           0.8561        +0.0474
  D3              0.7136           0.7789        +0.0653

Both detectors improved under attack. D2 improved less than D3.

Speaker notes: The adversarial experiment was designed to test whether synonym substitution could help phishing sentences evade detection. The result was the opposite: both systems improved. The mechanism is Laplace smoothing — when a synonym creates a three-word sequence never seen in the ham training corpus, the trigram count is zero and Laplace assigns probability 1/(context_count + V). With V ≈ 40,000, this gives surprisal ≈ 15+ bits, spiking H_lex. The substitute words are typically more formal or technical synonyms (WordNet lemmas prefer formal register), and formal vocabulary is rarer in casual work email than the original phishing vocabulary. H_syn is unaffected because _WN_POS_MAP only substitutes nouns, verbs, and adjectives with same-POS replacements — the grammatical role of the word in the sentence does not change. Note: adversarial.py uses NLTK word_tokenize for the substitution step, while features.py uses a custom regex tokeniser. This is a known inconsistency in the pipeline.

SLIDE 12 — ANTICIPATED EXAMINER QUESTIONS

Slide text (present as Q&A pairs, Q in bold accent colour, A in regular dark text):

Q: Why does D3 underperform D2?
A: Arc-label entropy overlaps almost completely between classes (mean difference 0.027 bits). Adding a non-discriminative feature injects noise into the Mahalanobis score and degrades separation.

Q: Why did obfuscation improve AUROC?
A: WordNet synonyms are rarer in ham context than the originals. Laplace scoring spikes surprisal on zero-count trigrams, making phishing more anomalous after substitution, not less.

Q: Why Laplace smoothing and not MLE?
A: MLE assigns P=0 to unseen tokens. The original implementation silently skipped zero-probability tokens. Phishing sentences had their most unusual words dropped from the H_lex average, scoring falsely normal.

Q: Why Mahalanobis and not Euclidean?
A: H_lex range is 11–15 bits; H_syn range is 2–4 bits. Euclidean is dominated by the larger-scale feature. Mahalanobis normalises for scale and accounts for the 0.44 correlation between the features.

Q: Why build from scratch?
A: Academic requirement. Ensures every step is understood and explainable, not treated as a library black box.

Q: Is 0.81 AUROC meaningful?
A: For a fully unsupervised one-class detector trained with no phishing examples, yes. Supervised classifiers on labelled data typically reach 0.95+ but require labelled attack examples and cannot generalise to novel attack types.

Q: What would you change?
A: Replace arc-label entropy with parse tree depth or imperative verb density. Use a larger modern phishing corpus. Run cross-corpus evaluation.

Speaker notes: The most dangerous question in this defence is "why does D3 underperform D2?" The correct answer requires three parts: (1) H_syn is non-discriminative — proven by the D1 AUROC of 0.4677, which is below chance; (2) adding a non-discriminative dimension to Mahalanobis distance adds noise without signal; (3) the covariance matrix is well-conditioned (condition number 5.5), so numerical instability is not the cause. The AUROC of 0.4677 for D1 means the detector is scoring phishing sentences LOWER than normal sentences — the opposite of what it should do. This happens because phishing H_syn values are concentrated near the normal mean, so normal sentences in the tails of the distribution (complex sentences with many clause types) score higher than average phishing sentences.

SLIDE 13 — LIMITATIONS AND FUTURE WORK

Slide text:
Current limitations:
- Arc-label entropy is a shallow syntactic feature — does not capture clause depth, subordination, or imperative mood
- SpamAssassin ham and Nazario phishing both date from the early 2000s — modern AI-generated phishing has different statistical properties
- Sentence-level evaluation inflates test set size; email-level aggregation strategy not formally evaluated
- No cross-corpus evaluation

Future directions:
- Replace H_syn with parse tree depth, branching factor, or imperative verb density
- Evaluate on a modern phishing corpus (post-2020 LLM-generated attacks)
- Cross-corpus evaluation: train on one corpus, test on another
- Explore whether correlation structure difference (r=0.44 normal vs r=0.08 phishing) can be directly exploited as a discriminative signal

Speaker notes: The most promising future direction identified during this project is the correlation structure difference. Normal email shows Pearson r = 0.44 between H_lex and H_syn; phishing email shows r = 0.08. This means the two classes occupy structurally different regions of the joint feature space even though their marginal H_syn distributions overlap completely. The current Mahalanobis detector encodes the normal covariance structure but does not directly test whether a new sentence's covariance pattern matches the normal or phishing regime. A detector that directly scores the difference in correlation structure — for example, using separate Gaussian fits for each class and comparing likelihoods — might extract discriminative signal from H_syn even though the H_syn marginal is useless on its own.

SLIDE 14 — CONCLUSION

Slide text:
- Objective: test whether joint entropy dissonance can detect phishing without labelled attack data
- H_lex alone: AUROC 0.8087 — strong unsupervised detection
- H_syn alone: AUROC 0.4677 — below chance, no useful signal
- Joint model (D3): AUROC 0.7136 — H_syn adds noise, not signal
- Adversarial result: synonym substitution increases detectability via Laplace surprisal inflation — OOV trigrams are more anomalous than the original vocabulary
- Key finding: the correlation structure of (H_lex, H_syn) differs between classes even when the H_syn marginal does not — a future discriminative signal not yet exploited

Speaker notes: The project's primary negative result — D3 underperforms D2 — is itself a meaningful contribution. It establishes a ceiling on what dependency-label entropy can contribute to phishing detection on this type of corpus, and it identifies exactly why: the H_syn marginal distributions are nearly identical across classes. The diagnostic work (D1 baseline, correlation analysis) provides a clean mechanistic explanation rather than simply reporting the failure. The adversarial result is an empirical demonstration of how Laplace smoothing creates an inherent resistance to vocabulary-level obfuscation: any substitution of uncommon formal vocabulary into phishing text will tend to increase H_lex rather than decrease it, as long as the language model is trained on informal workplace email. This is a non-obvious property of the system that only becomes visible through adversarial testing.
