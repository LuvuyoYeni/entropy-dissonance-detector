================================================================================
SECTION 1 — PROJECT OVERVIEW
================================================================================

WHAT THE PROJECT IS
The project builds and evaluates a one-class anomaly detector for phishing email.
"One-class" means the system is trained exclusively on legitimate (ham) email.
No phishing examples are seen during training. At inference time, each sentence in
a new email is scored; if the score exceeds a threshold, the sentence is flagged.

The project computes two information-theoretic features per sentence:
  H_lex — mean per-token surprisal under a custom trigram Laplace language model
  H_syn — Shannon entropy over the spaCy dependency arc label distribution

Three detectors are compared:
  D1 — H_syn only (univariate Gaussian anomaly detector)
  D2 — H_lex only (threshold at mean + 2 standard deviations)
  D3 — (H_lex, H_syn) jointly, scored via Mahalanobis distance from the
       bivariate Gaussian fitted on normal training sentences

WHAT PROBLEM IT SOLVES
Traditional phishing detectors use keyword lists or supervised classifiers.
Keyword lists fail when attackers rotate vocabulary. Supervised classifiers
require labelled phishing examples and cannot generalise to novel attack styles
that have not been seen at training time. One-class anomaly detection avoids
the labelling requirement entirely: if an email's statistical properties deviate
from learned normality, it is flagged regardless of the specific vocabulary used.

RESEARCH QUESTION
Can the joint distribution of lexical surprisal (H_lex) and syntactic entropy
(H_syn) per sentence, fitted only on legitimate email, detect phishing sentences
as anomalies without any labelled phishing examples at training time?

NOVEL CONTRIBUTION
(1) The specific combination of trigram LM surprisal and dependency-label entropy
    in a bivariate Gaussian one-class detector is not standard in prior work on
    email anomaly detection. The term "entropy dissonance" refers to the proposed
    asymmetry: phishing sentences inflate H_lex by using unusual vocabulary while
    keeping syntactic structure conventional, leaving H_syn near normal.
(2) The adversarial evaluation — WordNet synonym substitution — is an empirical
    test of whether the lexical signal can be evaded by vocabulary rotation.
(3) The D1 ablation (H_syn alone) provides a diagnostic component absent from
    comparable prior work: it isolates H_syn's discriminative contribution and
    explains why the joint model underperforms the H_lex-only baseline.

THE COUNTERINTUITIVE CORE FINDING
The hypothesis was: D3 (joint model) would outperform D2 (H_lex only). It does
not. D3 AUROC = 0.7136; D2 AUROC = 0.8087. The D1 ablation explains why:
H_syn AUROC = 0.4677, which is below chance, meaning H_syn is anti-discriminative
on this corpus. Adding a non-discriminative feature degrades the joint score.
This negative result is itself the scientific contribution — it identifies H_syn's
failure mode and points toward what a better syntactic feature would need to do.

--- SENTENCE TOKENISER (src/features.py:27–50) ---

Regex pattern:
  _SENT_SPLIT_RE = re.compile(r'(?<=[!?])\s+|(?<=[.])\s+(?=[A-Z])')

Logic:
  Always split after ! or ?
  Split after . only when the next character is a capital letter
  Before committing to a split, check the word immediately preceding the
  punctuation: if it matches the abbreviation set or is a single letter
  (initials), suppress the split

Abbreviation set (31 entries, case-folded):
  mr, mrs, ms, dr, prof, sr, jr, vs, etc, inc, ltd, corp, fig, vol, ed,
  approx, est, dept, no, st, ave, jan, feb, mar, apr, jun, jul, aug, sep,
  oct, nov, dec

Implementation: uses finditer() to locate all candidate split positions, walks
them in order, applies the abbreviation guard, and accumulates sentence strings
between committed split points. Returns empty list for empty input.

--- WORD TOKENISER (src/features.py:53–57) ---

Regex pattern:
  _WORD_RE = re.compile(r'[a-zA-Z]+')

Function: word_tokenize(text) = _WORD_RE.findall(text)

Keeps: alphabetic runs only
Discards: punctuation, digits, underscores, mixed alphanumeric tokens

--- TRIGRAM LANGUAGE MODEL (src/features.py:60–104) ---

Class: LaplaceTrigramModel
Data structures: three Python Counter dicts
  _unigrams: maps single word → count
  _bigrams:  maps (word_{i-1}, word_i) → count
  _trigrams: maps (word_{i-2}, word_{i-1}, word_i) → count

fit(sentences) — single O(n) pass:
  for each token at position i in each tokenised sentence:
    _unigrams[tok] += 1
    if i >= 1: _bigrams[(tok_{i-1}, tok)] += 1
    if i >= 2: _trigrams[(tok_{i-2}, tok_{i-1}, tok)] += 1
  _vocab_size = len(_unigrams)   [set after loop completes]

score(word, context) — context is a tuple of 0, 1, or 2 preceding tokens:
  V = _vocab_size (or 1 if unfitted)
  if len(context) >= 2:
    c_w   = _trigrams.get((context[-2], context[-1], word), 0)
    c_ctx = _bigrams.get((context[-2], context[-1]), 0)
  elif len(context) == 1:
    c_w   = _bigrams.get((context[0], word), 0)
    c_ctx = _unigrams.get(context[0], 0)
  else:
    c_w   = _unigrams.get(word, 0)
    c_ctx = sum(_unigrams.values())
  return (c_w + 1) / (c_ctx + V)

Laplace smoothing formula applied at query time:
  P(word | context) = (count(word, context) + 1) / (count(context) + V)
where V is the vocabulary size (~40,000 distinct word types after training).

Why MLE (no smoothing) failed:
  Without smoothing, unseen trigrams receive P = 0. The compute_h_lex function
  only appends a surprisal value when prob > 0 (see line 116). This silently
  drops OOV tokens from the average. Phishing sentences contain unusual word
  sequences — exactly the tokens that receive P = 0 under MLE. Their most
  anomalous tokens are excluded from the H_lex average, pulling phishing scores
  falsely toward the normal mean. Laplace smoothing fixes this: a zero-count
  trigram receives P = 1 / (c_ctx + V). With V ≈ 40,000 and c_ctx = 0, this
  gives P ≈ 0.000025, yielding surprisal ≈ 15.3 bits — correctly flagged.
  The AUROC before this fix is not recorded in the codebase.

--- H_lex (src/features.py:107–121) ---

Formula:
  H_lex = (1/n) × Σᵢ₌₁ⁿ⁻¹ [−log₂ P(wᵢ | wᵢ₋₂, wᵢ₋₁)]

Note: H_lex is MEAN surprisal, NOT entropy. Do not use the word "entropy"
when describing H_lex.

Context window:
  Loop runs from i=1 to len(tokens)-1 inclusive.
  context = tuple(tokens[max(0, i - NGRAM_ORDER + 1) : i])
  where NGRAM_ORDER = 3.
  For i=1: context = (tokens[0],) — one token, bigram probability
  For i=2: context = (tokens[0], tokens[1]) — two tokens, trigram probability
  For i≥3: context = (tokens[i-2], tokens[i-1]) — always two tokens, trigram

The function returns None if fewer than 2 alphabetic tokens. Upstream
extract_features() discards None values.

Stats on normal training data (D2 training split — 3,096 emails):
  Mean H_lex: 12.570 bits
  Std:         1.550 bits
  Threshold (D2): 12.570 + 2 × 1.550 = 15.669 bits (set by BaselineDetector.fit, k=2.0)

Stats on normal training data (D3 training split — 2,709 emails):
  Mean H_lex (mu_[0]): 12.696 bits   [printed by JointEntropyDetector.fit]

--- H_syn (src/features.py:124–138) ---

Formula:
  H_syn = −Σₖ pₖ × log₂(pₖ)
where pₖ = count(label k) / total labels in the sentence.
This is standard Shannon entropy over a discrete label distribution.

What spaCy provides:
  NLP = spacy.load("en_core_web_sm", disable=["ner"])
  doc = NLP(sentence)
  labels = [token.dep_ for token in doc if token.dep_ != ""]

Arc label examples (Universal Dependencies subset used by en_core_web_sm):
  nsubj    — nominal subject
  dobj     — direct object
  det      — determiner
  prep     — prepositional modifier
  ROOT     — root (typically the main verb)
  amod     — adjectival modifier
  advmod   — adverbial modifier
  punct    — punctuation
  pobj     — object of preposition
  aux      — auxiliary verb

A sentence with many diverse label types has high H_syn (high variety).
A sentence dominated by one or two roles has low H_syn (low variety).
Returns None if fewer than 2 labels; this sentence is dropped upstream.

Stats on normal training sentences:
  Mean H_syn: 3.401 bits    [reported by analysis/feature_correlation.py]

Stats on phishing test sentences:
  Mean H_syn: approximately 3.374 bits   [inferred from 0.027-bit difference]
  Mean difference: 0.027 bits (< 2% of one standard deviation)

Pearson correlation between H_lex and H_syn:
  Normal training set:   r = 0.44 (moderate positive)
  Phishing test set:     r = 0.08 (near zero)
  Both values from analysis/feature_correlation.py, confirmed reproducible.
  This structural difference (r=0.44 vs r=0.08) is identified in the code as
  a "potentially useful finding for the paper" that is not yet exploited.

--- BIVARIATE GAUSSIAN (src/full_system.py:14–79) ---

Mean vector:
  self.mu_ = X.mean(axis=0)
  mu_ = [H_lex: 12.696, H_syn: 3.401]   [from code printout]

Covariance matrix — computed manually (no numpy.cov()):
  n = len(X)
  diff = X - self.mu_
  cov = np.zeros((2, 2))
  for row in diff:
      for i in range(2):
          for j in range(2):
              cov[i][j] += row[i] * row[j]
  cov = cov / (n - 1)    # unbiased sample covariance

Fitted covariance matrix values:
  cov = [[1.4950,  0.3306],
         [0.3306,  0.3769]]

Interpretation:
  cov[0][0] = 1.4950: variance of H_lex on training set (std ≈ 1.222 bits)
  cov[1][1] = 0.3769: variance of H_syn on training set (std ≈ 0.614 bits)
  cov[0][1] = cov[1][0] = 0.3306: covariance (captures r=0.44 correlation)

Matrix health (from analysis/feature_correlation.py):
  Condition number: approximately 5.5 (well-conditioned; threshold for concern = 30)
  Determinant: approximately 0.453 (well above zero; no near-singularity)
  np.linalg.pinv fallback in the code was never triggered.

Inverse:
  self.sigma_inv_ = np.linalg.inv(cov)   [pinv fallback never triggered]

--- MAHALANOBIS DISTANCE (src/full_system.py:81–83) ---

Formula:
  D(x) = √((x − μ)ᵀ Σ⁻¹ (x − μ))

Code:
  def _mahalanobis(self, h_lex, h_syn):
      x = np.array([h_lex, h_syn]) - self.mu_
      return float(np.sqrt(x @ self.sigma_inv_ @ x))

Why Mahalanobis and not Euclidean:
  H_lex and H_syn are on different scales (H_lex range ~11–15 bits; H_syn range
  ~2–4 bits). Euclidean distance is dominated by the larger-scale axis.
  Mahalanobis normalises by the covariance matrix, so both features contribute
  proportionally to their variance. It also accounts for the positive correlation
  (r=0.44), rotating the distance metric to align with the principal axes of the
  normal data cloud.

Threshold selection (tau):
  Primary method: F1-optimal threshold search on the validation set.
    All thresholds from sklearn roc_curve() are tried. For each, TP, FP, FN are
    computed manually and F1 is calculated. The threshold maximising F1 is selected.
  Safety fallback: If the F1-optimal threshold would flag > 80% of all validation
    sentences as positive (positive_rate > 0.80), fall back to the 95th percentile
    of Mahalanobis distances on normal training data.
  Fitted tau value: 1.4625   [from results/three_way_comparison.csv context]

--- ADVERSARIAL EXPERIMENT (src/adversarial.py) ---

Method:
  SUBSTITUTION_RATE = 0.30 (30% of eligible content words per sentence)
  RANDOM_SEED = 42
  Tokeniser: NLTK word_tokenize + nltk.pos_tag  (NOT the custom regex tokeniser)
  POS tags eligible for substitution:
    Nouns:      NN, NNS, NNP, NNPS → wordnet.NOUN
    Verbs:      VB, VBD, VBG, VBN, VBP, VBZ → wordnet.VERB
    Adjectives: JJ, JJR, JJS → wordnet.ADJ
  Adverbs, determiners, prepositions, pronouns are NOT eligible.

Synonym selection (_get_synonym):
  For each eligible word: iterate synsets for that word+POS via wordnet.synsets()
  Take the first lemma from the first synset whose:
    (a) name is different from the original word
    (b) name contains only alphabetic characters (no underscores or hyphens)
  Preserve capitalisation: if original word starts with uppercase, capitalise
  the replacement. If no synonym found, keep original word.

Obfuscation:
  For each sentence: select n_replace = max(1, round(n_eligible × 0.30)) indices
  at random (using seeded rng.sample()). Replace those tokens with their synonyms.
  Sentences are joined back with spaces. Full text is joined from obfuscated
  sentences using NLTK sent_tokenize (not the custom tokeniser).

Known inconsistency:
  adversarial.py uses NLTK word_tokenize and sent_tokenize for the substitution
  step. features.py uses a custom regex tokeniser for all scoring. The obfuscated
  text is passed back through the scoring pipeline using the custom tokeniser.
  Token boundaries may differ slightly between the two tokenisers. This is a
  known limitation acknowledged in the WALKTHROUGH_SCRIPT.

Full adversarial results (from results/three_way_comparison.csv):
  Detector  Features      Clean AUROC  Adversarial AUROC  Delta
  D1        H_syn         0.4677       0.4923             -0.0246
  D2        H_lex         0.8087       0.8561             -0.0473
  D3        H_lex+H_syn   0.7136       0.7789             -0.0653

Delta = clean - adversarial. NEGATIVE delta means adversarial AUROC was higher
(i.e., the attack improved detectability — the opposite of the intended effect).

Explanation for improvement under attack:
  WordNet synonyms tend toward formal or technical register. When a synonym
  replaces a word in a phishing sentence, the resulting three-word trigram
  sequence is very likely to have zero count in the ham-trained language model
  (the training corpus is informal workplace email from the early 2000s).
  Laplace assigns P = 1 / (c_ctx + V) ≈ 1/40,000 to zero-count trigrams,
  giving surprisal ≈ 15.3 bits. This spikes H_lex for the substituted sentence,
  pushing it further from the normal distribution, not closer.
  The attack does not help phishing evade detection. It makes it more detectable.

Hypothesis status:
  The adversarial.py code checks: if d2_degradation > d3_degradation → print
  "consistent with stated hypothesis". Both degradation values are negative
  (both systems improved). Since -0.0473 > -0.0653, the FIRST branch fires and
  the code prints "consistent with the stated hypothesis."
  This is arithmetically triggered but substantively misleading: the hypothesis
  was that D2 would degrade under attack while D3 would be more robust. Neither
  degraded. D3 improved MORE than D2 (+0.0653 vs +0.0474). The hypothesis
  assumed degradation would occur. It did not.
  The paper must not claim the hypothesis was confirmed. It must explain the
  OOV inflation mechanism and present the improvement as the actual finding.

SECTION 5 — WHAT THE PAPER MUST ARGUE
================================================================================

CLAIM 1: H_lex from a custom trigram Laplace LM achieves AUROC 0.8087 for
one-class phishing detection without any labelled phishing examples.
Evidence: D2 AUROC = 0.8087 on 775 normal and 259 phishing held-out test emails.
Status: FULLY SUPPORTED. Argue this strongly.

CLAIM 2: H_syn (dependency-label entropy) carries no discriminative signal for
phishing detection on the SpamAssassin/Nazario corpus at the sentence level.
Evidence: D1 AUROC = 0.4677 (below chance). Mean H_syn difference = 0.027 bits.
Status: FULLY SUPPORTED. This is the primary diagnostic contribution.
Framing: Not a failure of the system — a positive finding that identifies H_syn's
limitations on this data and points toward better syntactic features.

CLAIM 3: Adding a non-discriminative feature to a Mahalanobis detector degrades
performance (D3 AUROC = 0.7136 < D2 AUROC = 0.8087).
Evidence: Direct comparison of AUROC values. Explained mechanistically by D1.
Status: FULLY SUPPORTED.

CLAIM 4: The correlation structure of (H_lex, H_syn) differs between normal
(r=0.44) and phishing (r=0.08) sentences, suggesting that the joint distribution
carries information not captured by the H_syn marginal alone.
Evidence: analysis/feature_correlation.py output.
Status: SUPPORTED AS AN OBSERVATION. The paper should present this as a finding
and future direction, NOT as a result exploited by the current system.

CLAIM 5: Synonym substitution (30% rate, WordNet) increases AUROC for all three
detectors due to OOV trigram inflation in the ham-trained language model.
Evidence: All three AUROC values increase; OOV mechanism is explained.
Status: SUPPORTED. The paper must NOT frame this as "the system is robust to
synonym attacks." It must frame this as: "synonym substitution backfires because
WordNet replacements create low-probability trigrams in a ham-trained LM."

CLAIM 6: The system is a genuine one-class anomaly detector — no labelled
phishing data is used at any stage of training.
Evidence: Both D2 and D3 fit() methods receive only normal_texts.
Status: FULLY SUPPORTED and central to the novelty argument.

DO NOT CLAIM:
- That D3 is more robust than D2 to adversarial attack (both improved; D3
  improved more, but because its score is further from the threshold, not because
  it is architecturally more robust).
- That the adversarial hypothesis was confirmed in the conventional sense.
- That H_syn contributes discriminative signal in the joint model.
- That the 0.8087 AUROC demonstrates the system is deployment-ready (it does not
  — no document-level aggregation evaluation was done, and the corpus is 20+ years
  old).

SECTION 6 — HONEST LIMITATIONS
================================================================================

LIMITATION 1: H_syn is non-discriminative on this corpus.
H_syn AUROC = 0.4677, below random chance. The entire research hypothesis
(that joint modelling would outperform lexical-only) is falsified by the data.
The paper must acknowledge this. It is NOT appropriate to state "D3 shows
comparable performance to D2" — D3 is worse by 0.095 AUROC points.

LIMITATION 2: The adversarial result is counterintuitive and not what the
experiment was designed to show.
The experiment was designed to test whether synonym rotation could evade the
detector. Both systems improved under attack. The printed output in adversarial.py
says "consistent with the stated hypothesis" only in an arithmetic sense:
D2 improved less than D3 (+0.0474 vs +0.0653). But the hypothesis assumed
degradation, not improvement. The paper must give the OOV inflation explanation.

LIMITATION 3: Sentence-level AUROC as the evaluation metric is imprecise.
One email contributes multiple test points (multiple sentences). Sentences from
the same email are not independent. The class ratio at the sentence level
(approximately 4:1–5:1 normal-to-phishing) is not explicitly reported or
accounted for. No document-level aggregation strategy (e.g., max sentence score,
mean score, fraction above threshold) was evaluated.

LIMITATION 4: Corpus age and distribution.
SpamAssassin and Nazario corpora are from 2002–2006. Modern phishing email,
especially AI-generated phishing, has different statistical properties. The
system's behaviour on contemporary phishing is unknown.

LIMITATION 5: H_syn small-sample bias.
Shannon entropy estimated from 5–10 dependency labels has known upward bias
proportional to (k-1)/(2n) (Miller-Madow correction). No correction is applied.
This adds noise to H_syn estimates for short sentences.

LIMITATION 6: Sentence filter is calibrated by characters, not tokens.
extract_features() drops sentences shorter than 20 characters. A 4-word
sentence like "Click here now please." (22 characters) passes the filter
but has too few tokens for reliable H_syn estimation.

LIMITATION 7: Tokeniser inconsistency in the adversarial module.
adversarial.py uses NLTK word_tokenize and sent_tokenize. features.py uses
the custom regex tokeniser. The obfuscated text passes through both. Token
boundaries may differ at punctuation and contractions. The effect is likely
minor but introduces noise in the adversarial evaluation.

LIMITATION 8: D3 threshold selection.
The F1-optimal threshold from the validation set (tau=1.4625) may overfit
the validation distribution. No cross-validation was performed.
